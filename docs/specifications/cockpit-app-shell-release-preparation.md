# Cockpit App Shell — release-candidate preparation

**Status:** Candidate tooling only. This does not authorize distribution or publication.

## Build locally

From the repository root, with Git and Node.js available:

```sh
node --test web/tests/appShellDistribution.test.js web/tests/appShellReleasePrep.test.js
node web/scripts/prepare-app-shell-release.js 0.1.0-rc.1
```

This copies the exact `web/appShell.js` bytes into `web/dist/cockpit-app-shell-0.1.0-rc.1.js` and writes a JSON manifest recording the source repository, current Git commit, artifact name, and SHA-256 digest. The script does not publish, sign, tag, upload, or modify Portal.

`web/dist/` is an output directory, not a committed distribution. Keep generated candidates out of version control and treat the manifest as a provenance *record*, not an independently verified attestation.

## Release gates (not yet satisfied)

1. Cockpit owner makes and documents the licensing and redistribution decision.
2. Maintainers review the exact source commit and ensure a clean build tree.
3. CI independently reproduces and checks artifact hash against the manifest.
4. Release signing/provenance, immutable version tag and storage, and rollback are approved.
5. GC Portal verifies the artifact hash, compatibility, CSP, keyboard accessibility, and responsive behavior before consumption.
6. Any deployment or approval/AI functionality undergoes separate security review.

The candidate manifest deliberately sets `distributionApproved: false`. Do not treat the existence of generated bytes as permission to bundle or deploy them.
